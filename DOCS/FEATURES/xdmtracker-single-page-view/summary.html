The phantom page view

How a personalization display notification deflated our Bounce Rate —
and why we fixed it in acdl_helper, not in Adobe Analytics.

The setup

One page-view event that also rendered Target offers:

alloy("sendEvent", {
  renderDecisions: true,
  xdm: { web: { webPageDetails: {…} } }
})

The hidden default

With renderDecisions: true the Web SDK defaults to sendDisplayEvent: true — firing a second call: the display notification (decisioning.propositionDisplay) that tells A4T a personalization was shown.

Root cause — a second, auto-collected hit

The key insight

Adobe Analytics decides page view vs. link click purely from web.webPageDetails vs. web.webInteraction — not from eventType.
  • The Web SDK auto-collects web.webPageDetails.URL on every event.
  • The display notification has no webInteraction → looks like a page view.
  • The docs claimed AA auto-drops that event. It didn't.

When docs and observed behavior disagree — observed behavior wins.

What didn't work

✕ A custom AA metric

Subtract the extra page view in a calculated metric.

Masks it in one report. The bad hit is still collected — every other report, segment and export stays wrong.

✕ Rely on eventType

Trust the docs that decisioning.propositionFetch is ignored.

Assurance proved it was still recorded as a page view. eventType doesn't govern classification — web.* does.

Also rejected: disabling rendering (breaks the feature) · killing display events globally (breaks A4T).

How we proved it

Not from docs — from the wire, in Adobe Experience Platform Assurance.

  • Watched the real collect calls in the Adobe Analytics view.
  • Two hits per load; the second had an auto-added URL and no webInteraction.
  • Counted as a page view regardless of eventType.
  • Setting com_adobe_analytics.enabled = false stops the Edge forwarding the event to Analytics — it still sends and reaches the datastream; only the AA hit is gone. Target/AEP unaffected.

Solution — two ordered events

Takeaways

  • Verify, don't trust. Adobe docs were wrong twice — confirm in Assurance.
  • Classification is the web.* object, not eventType.
  • Fix the cause, not the report. Remove the bad hit, don't patch reporting.
  • Order + a safety timeout. Fetch first → unified page view, gated but never hanging.

Appendix · the gotcha

Deactivating AA collection

The Web SDK auto-injects web.webPageDetails.URL on every event — so omitting the classifier is not enough. Disable Analytics at the Edge:

alloy("sendEvent", {
  xdm: { eventType: "decisioning.propositionFetch" },
  renderDecisions: true,
  // ↑ the Web SDK STILL auto-adds web.webPageDetails.URL here
  edgeConfigOverrides: {
    // the only deterministic AA off-switch:
    com_adobe_analytics: { enabled: false }
  }
})
  • Analytics — records nothing: no page view, no link click.
  • Target / AEP — still receive the event in full.
